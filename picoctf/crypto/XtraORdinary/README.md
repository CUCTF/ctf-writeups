# XtraORdinary

## Summary
Challenge Description:
```
Check out my new, never-before-seen method of encryption! I totally invented it myself. I added so many for loops that I don't even know what it does. It's extraordinarily secure!
```

Artifacts:
- 'chall/encrypt.py': the python source code provided by the challenge authors containing the encryption algorithm used to generate the ciphertext
- `chall/output.txt`: the ciphertext generated by the challenge authors using `chall/encrypt.py`
- `solve.py`: the solve script that exploits the vulnerability and recovers the flag

This challenge provides an encryption scheme that encrypts a flag by XORing it with a key and several fixed strings multiple times. The exploit uses the provided strings and flag format knowledge to recover the flag.

## Context
The encryption algorithm works in two stages:
1) XOR the flag plaintext with some private key to generate `ctxt`.
2) XOR each string in `random_strs` with `ctxt` a random number of times determined by the nested `randint()` calls.

```
def encrypt(ptxt, key):
    ctxt = b''
    for i in range(len(ptxt)):
        a = ptxt[i]
        b = key[i % len(key)]
        ctxt += bytes([a ^ b])
    return ctxt

ctxt = encrypt(flag, key)

random_strs = [
    b'my encryption method',
    b'is absolutely impenetrable',
    b'and you will never',
    b'ever',
    b'ever',
    b'ever',
    b'ever',
    b'ever',
    b'ever',
    b'break it'
]

for random_str in random_strs:
    for i in range(randint(0, pow(2, 8))):
        for j in range(randint(0, pow(2, 6))):
            for k in range(randint(0, pow(2, 4))):
                for l in range(randint(0, pow(2, 2))):
                    for m in range(randint(0, pow(2, 0))):
                        ctxt = encrypt(ctxt, random_str)
```

## Vulnerability
The key vulnerabilities of the encryption algorithm are that 1) the nested loops reduce to a parity problem and 2) we have access to the `random_strs` used during encryption.

After XORING the original flag plaintext with a private key to generate `ctxt`, the encryption algorithm tries to add randomness by performing `encrypt(ctxt, random_str)` some random number of times provided by `randint()` in the numerous for loops. Despite complex for loop representation, the for loops can be simplified to a single loop as such:
```
for random_str in random_strs:
    for i in range(randint(0, pow(2,8)) * randint(0, pow(2, 6)) ... * randint(0, pow(2,0))):
        ctxt = encrypt(ctxt, random_str)
```

Furthermore, this loop does not make the ciphertext any more obscure. Since XOR is self-inverse: `(ctxt ^ key) ^ key = ctxt`, the only thing that matters is whether the total number of applications is odd or even. If odd, `ctxt` is XORed with `random_str` once. If even, `ctxt` is not modified at all as the `random_str` applications get cancelled out.

With the `random_strs` values also being public, we can generate all possible combination of `random_strs`. By applying each combination to the ciphertext, we get up to 32 possible candidates for `ctxt`. Note that even though `random_strs` contains multiple `b'ever'` entries, XORing with the same string only affects the parity value and therefore does not change the overall possible combinations.

Another vulnerability is that we partially know the plaintext as the flag starts with "picoCTF{". By XORing `ctxt` with "picoCTF{", we can at least partially recover the private `key` used. This would help us recover at most 8 letters of the key or even the full key if `len(key) <= 8`.

## Exploitation
The exploit involves XORing the ciphertext with all possible combinations of `random_strs` to generate the 32 `ctxt` candidates and using these candidates to recover the private `key`.

```
for r in range(1, len(random_strs) + 1):
    for c in itertools.combinations(random_strs, r): # generate all possible combinations of random_strs
        ret = ciphertext
        for str in c:
            ret = encrypt(ret, str)
```

With these 32 candidates for `ctxt`, we can now generate possible candidates for the key as well. With each `ctxt` candidate, we XOR it with "picoCTF{", the known part of the flag to reveal the first 8 bytes of the private `key`. Since real keys are often human-readable, we look for any result that resembles a word.

```
...
Ii7üht6J
Mq6,tm&
Jg7ij2'Y
Mc7zdd+_
Iä6(xå;
Africa!A
...
```

We can see that XORed results contain "Africa!". Using this key to decrypt each of the 32 candidates, we find one that starts with "picoCTF{", thereby solving the challenge.

## Remediation
The encryption algorithm should try to hide the strings that were used in the XOR process and avoid reusing any keys when XORing. Without knowing the strings used during encryption, an attacker cannot reconstruct the possible ciphertext candidates, making this brute-force approach infeasible.
